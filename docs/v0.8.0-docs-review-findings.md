## (b) Install paths — versioned vs. version-free URLs (#340)

### B1 (High) — version-free `.deb` URL in getting-started.md → 404-prone (#340)

- **Where:** `docs/getting-started.md:46` (Debian/Ubuntu install block).
- **What's wrong:** Used
  `https://github.com/spelunk-cloud/spelunk/releases/latest/download/spelunk_<version>_amd64.deb`.
  This is the exact #340 failure mode: `releases/latest/download/` is the
  version-free path, but the asset filename embeds `<version>`. GitHub's
  `latest/download/<asset>` only resolves when the asset name is exact and
  version-free; a versioned filename under `latest/download/` 404s. `releasing.md`
  itself warns about this at lines 127-129.
- **Correct value:**
  `https://github.com/spelunk-cloud/spelunk/releases/download/v<version>/spelunk_<version>_amd64.deb`
  (tag-pinned form, matching `releasing.md:124`). Note the tag segment is
  `v<version>` (with the `v`) while the `.deb` filename uses the bare version
  (no `v`).
- **Doc fix vs. code/issue:** Doc fix, within remit. **FIXED** in this worktree —
  rewrote the block to the tag-pinned URL and added a one-line note explaining why
  the version-free form 404s.

**Other install URLs verified correct (no change needed):**

- `docs/getting-started.md` manual-tarball block (lines 60-61) already uses the
  tag-pinned `releases/download/<version>/…` form. Good.
- `docs/releasing.md` "Download URLs" section (lines 100-129) uses tag-pinned
  forms throughout and explicitly documents the #340 caveat. Good. The single
  mention of `releases/latest/download/<asset>` (line 127) is in a note correctly
  explaining it "also works when the asset name is exact" — accurate, not a bug.
- `README.md` quick-start uses the `install.sh` one-liner and a link to the
  releases page — no hardcoded version-free download URL. Good.
